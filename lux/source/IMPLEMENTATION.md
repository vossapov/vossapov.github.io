# Lux — локальне демонстраційне середовище

Запуск на цьому комп’ютері:

```bash
cd /home/vossapov/lux
bash start.sh
```

Відкрити http://localhost:8080. З телефона в тій самій мережі — `http://<IP-комп’ютера>:8080`. Сервер за замовчуванням слухає локальні інтерфейси; для доступу лише з цього комп’ютера запустіть `LUX_HOST=127.0.0.1 bash start.sh`. Публічна статична версія: https://vossapov.github.io/lux/. Вона використовує JSON-каталог, CLIP у браузері й готові українські аудіовідповіді; Python-сервер назовні не відкривається.

## Що працює

- 30 вигаданих товарів у SQLite, пошук артикулу зі збереженням нулів, назви, ключових слів та простих голосових запитів.
- Випадаючий список із клавіатурною навігацією, картки товарів, нульовий залишок, категорії.
- Завантаження/фотографування товару: локальна CLIP vision ONNX порівнює з фото каталогу. Повертається список схожих позицій; точне фото з каталогу відкриває картку відразу. Оцінка подібності не є ймовірністю чи гарантією правильного артикулу. Розміри/модифікації треба звіряти.
- Голосовий пошук через browser SpeechRecognition (`uk-UA`). Один запуск і дозвіл на мікрофон, потім повторні запити. Обмежений словник пошуку, не універсальний LLM. Розпізнавання залежить від браузера й може використовувати його зовнішній сервіс; офлайн-розпізнавання не заявлено.
- Озвучення результату українською через локальний eSpeak NG. Синтез роботизований, без хмарного TTS. При неоднозначності — список варіантів, при відсутності — чесна порожня відповідь.
- Кампанія Halloween, вкладки Проєкти/Файли, завантаження PNG/PDF/ZIP, дослідження й база бренду.

## Телефон, камера й голос

Текстовий пошук і файли працюють через звичайний LAN HTTP. Поле вибору фото з `capture=environment` пропонує камеру на сумісних телефонах. Поведінку камери визначає ОС/браузер. Доступ до мікрофона потребує HTTPS або localhost і сумісного браузера. Для голосового показу з телефона налаштуйте довірений HTTPS reverse proxy; сертифікат не можна замінити обходом попередження браузера. Firefox та вбудований браузер можуть не надавати SpeechRecognition; у демо є текстове введення запиту й озвучення.

## Дані та структура

- `demo/dist/catalog.json`: єдине джерело демонстраційних назв, цін, залишків, знижок.
- `demo/catalog.sqlite`: створюється з JSON під час запуску. Обслуговування запитів використовує SQLite у режимі читання. До обліку магазину не підключено.
- `demo/dist/assets/products/`: 30 згенерованих ілюстративних фото, не фото реального асортименту.
- `demo/models/clip-vision.onnx`: відкрита квантована CLIP vision модель Xenova/clip-vit-base-patch32. Джерело: https://huggingface.co/Xenova/clip-vit-base-patch32. Збережена локально.
- `demo/vendor/`: ONNX Runtime та залежності для Python 3.12 Linux; для іншого середовища перевстановіть залежності.
- `research/report.html`: дослідження з вбудованим візуальним архівом.
- `research/sources.json`, `research/brand-guide.json`: джерела та робочі правила стилю.
- `deliverables/proposal-owner.txt`: готовий текст для власника; не надсилався.
- `scripts/generate_campaign.py`: відтворювані макети з точними даними каталогу.

Модель і фото можуть робити перший фотозапит повільнішим: сервер будує вектори каталогу та кешує їх у пам’яті. Знімки запитів не записуються на диск і не надсилаються в зовнішній сервіс.

Для перенесення: Python 3.12, `Pillow`, `numpy`, `onnxruntime`, системний `espeak-ng` з українським голосом. Для повторної генерації макетів додатково `reportlab`, `pypdf`, Poppler. Базові інтерфейс, шрифти, фото, модель і макети локальні.

## Межі демонстрації

Авторизація відсутня за умовами демонстрації. Не виставляйте цей сервер у публічний інтернет. Перед робочим пілотом потрібні узгоджене джерело читання обліку, актуальність/значення залишків, контроль доступу та перевірка на пристроях працівників.

Ціни, кількості, артикули, акція 24–31.10.2026 і знижки вигадані. Основна адреса взята з Instagram — Вільна,1; розбіжності в інших джерелах описані у звіті. Стиль реконструйовано з публічної реклами, офіційного брендбука немає. Логотип збережено без перемальовування; його малу роздільність слід замінити оригіналом перед великим друком. PDF — макети для погодження, остаточні друкарські профілі/вимоги не отримані.

## Перевірка

`scripts/check_demo.py` перевіряє артикул, неоднозначність, відсутність товару, нульовий залишок, усі розрахунки знижок, точний і змінений знімок у CLIP. Ключ `--http` додатково перевіряє API й український WAV. Перевірки інтерфейсу проводяться у браузері на ПК та мобільній ширині.

## GitHub Pages

Публічні файли розміщено в `lux/` репозиторію `vossapov/vossapov.github.io`. Робоча копія: `.publish-worktree`. Експорт: `python scripts/export_static.py .publish-worktree/lux`. Перше розпізнавання нового фото завантажує приблизно 89 МБ моделі, аналіз відбувається на пристрої. HTTPS дозволяє запитувати доступ до мікрофона у сумісному браузері.

## Кампанії, генерація та SMM

Маркетинг містить вкладки «Промокампанії» та «SMM». Навігація: список кампаній → назва й опис кампанії → набори → окремі макети. Halloween створена за замовчуванням.

Майстер нової кампанії:
1. Назва, текстовий або голосовий опис, фото чи список товарів. Приймає JPG/PNG/WebP, PDF, CSV/TSV та XLSX; до 8 файлів по 12 МБ. Для PDF — текст і перші 4 сторінки зображень.
2. Codex розпізнає дати, категорії, артикули, завдання й формати. Якщо все відомо — одразу підсумок; інакше поля для уточнення, пошук товарів, необов’язкові категорії, соцмережі, друк A5/A4/A3/A2 та побажання. Невідомі артикули показуються для перевірки, не підміняються випадковими товарами.
3. Після підтвердження створюються окремі завдання на товар × формат. Кожне має опис, редагований промпт, власне фото або пошук точного фото в каталозі. Зображення з інтернету автоматично не завантажуються.
4. Генерація через локальний Codex; статуси черги, помилки з повтором, перегенерація з побажаннями, історія версій. Кожний запит включає бриф, точні дані товару, контакти, правила бренду, логотип і попередні банери як стильові приклади. Для повторної генерації додається попередня версія.

Нові кампанії, вкладення й завдання зберігаються в `demo/creative-data/` поза публічним каталогом. Чернетка брифу залишається в браузері. Після перезапуску незавершені завдання отримують статус помилки й можуть бути повторені. Генерація виконується послідовно; максимум 60 макетів у кампанії. Сформовані PNG мають заданий розмір, друковані варіанти також отримують PDF 300 dpi у RGB: це макети для погодження, а не перевірена CMYK-підготовка до друкарні.

### Підключення Codex без API-ключа

Потрібні локальний сервер, Codex CLI і вхід у ChatGPT: `codex login`. Статус: `codex login status`. За потреби вкажіть виконуваний файл через `LUX_CODEX_BIN`. На цьому ПК перевірено CLI 0.154.0 та вхід через ChatGPT, реальну генерацію й повторну генерацію PNG, розбір тексту й фото списку артикулів.

Сервер запускає `codex exec` із структурованою відповіддю та збереженим входом ChatGPT. Він не витягує токени з desktop-застосунку, не передає їх браузеру та не використовує API-ключі. Генератор повинен мати доступний вбудований інструмент зображень; за його відсутності повертається помилка, а не підставний макет. Запити використовують ліміти облікового запису Codex. Однієї лише наявності desktop-застосунку на іншому ПК недостатньо: потрібен налаштований CLI.

Офіційні джерела: [автентифікація Codex](https://learn.chatgpt.com/docs/auth), [неінтерактивний режим](https://learn.chatgpt.com/docs/non-interactive-mode), [генерація зображень](https://learn.chatgpt.com/docs/image-generation).

Міст генерації доступний тільки через localhost/127.0.0.1 на цьому ПК; перевіряються Host, Origin і токен поточного запуску. Не призначений для доступу з відкритого інтернету. Фото й опис із брифу передаються Codex при аналізі/генерації. Публічна статична версія не запускає CLI. Текстовий каталог і демомапа залишаються доступними через звичайний локальний сервер у мережі.

### Перегляд і публікація

Прев’ю відкриває перегляд на сторінці; назва плитки відкриває набір. Окреме завантаження повертає PNG/PDF, «Завантажити всі» формує ZIP лише з файлів поточного набору або кампанії. Старий флаєр доступний для перегляду на всіх 4 сторінках.

«Публікація» кампанії, «Опублікувати всі» набору й «Опублікувати» макета відкривають локальну симуляцію з відповідними файлами. Сторінки Instagram / Stories / Facebook / Threads залежать від форматів. Можна обрати зараз або майбутню дату й редагувати текст. Тексти соціальних дописів у цій формі все ще генеруються локальними шаблонами. Друковані PDF доступні для завантаження.

SMM показує заплановані й опубліковані записи, дозволяє публікувати із черги вручну, скасовувати та прибирати записи з історії. Записи публікацій зберігаються в localStorage (`lux-smm-posts-v1`); між пристроями не синхронізуються. Реального надсилання в соцмережі й фонового виконання за розкладом немає.

## Мапа магазину

На сторінці товару одразу відображається мапа без кнопки відкриття й налаштувань: секція товару, маршрут і демопозиція користувача. Орієнтовна схема за наданим виглядом будівлі: суцільний зал, 15 рядів по 5 секцій, стелажі біля стін, парковка вздовж правого фасаду, два входи на різних кінцях фасаду. Точний внутрішній план невідомий.

`storeLocation` кожного товару містить `row`, `section`, `shelf`. Наявні ряди й секції збережено; полиця 1 — демонстраційне значення, оскільки номерів полиць у початкових даних немає. 30 товарів займають початкові ряди 1–6; інші секції доступні для вибору, але порожні в каталозі. Дані SQLite і статичного фотокаталогу узгоджено з JSON.

Мапа відображається тільки в картці товару без кнопок і налаштувань. З головної сторінки кнопку мапи прибрано. Це симуляція GPS: справжня геолокація не запитується. Прив’язка до географічних координат та реальне визначення позиції всередині будівлі не реалізовані.

## Перевірки нових сценаріїв

- `python scripts/check_creative.py`: імпорт фото, CSV/XLSX, збереження артикулів, бриф і брендконтекст, валідація, локальні обмеження мосту, відсутність API-ключів.
- `node scripts/check_marketing.js`: склад одиночних і групових публікацій, планування, помилки, ZIP-оригінали.
- `node scripts/check_store_map.js`: 30 прив’язок товарів і 150 маршрутів від обох входів до всіх секцій; перетинів стелажів немає.

Майстер, підтвердження, перехід до генерації, мобільна мапа та рух позиції перевірені в браузері.
